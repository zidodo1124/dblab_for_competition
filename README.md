全国大学生计算机系统能力大赛数据库管理系统赛道，以培养学生“数据库管理系统内核实现”能力为目标。本次比赛为参赛队伍提供数据库管理系统代码框架RMDB，参赛队伍在RMDB的基础上，设计和实现一个完整的关系型数据库管理系统，该系统要求具备运行TPC-C基准测试（TPC-C是一个面向联机事务处理的测试基准）常用负载的能力。

RMDB由中国人民大学数据库教学团队开发，同时得到教育部-华为”智能基座”项目的支持，平台、赛题和测试用例等得到了全国大学生计算机系统能力大赛数据库管理系统赛道技术委员会的支持和审核。系统能力大赛专家组和[101计划数据库系统课程](http://101.pku.edu.cn/courseDetails?id=DC767C683D697417E0555943CA7634DE)工作组给予了指导。

### 题目四：查询优化与执行

本题主要围绕查询计划优化展开，核心思路是在保持查询语义不变的前提下，将选择、投影尽可能前移，并根据表规模和连接条件调整多表连接顺序，减少中间结果数量。实现中重点处理了单表谓词下推、跨表连接条件保留、投影列裁剪和执行计划输出格式等问题。

开发过程中最容易出错的是 `basic_query_test8` 相关的隐藏场景：一开始下推条件时没有严格区分单表谓词和跨表谓词，导致部分过滤条件被放到错误位置；投影下推也曾遗漏后续过滤或输出仍需使用的列，造成结果不一致。最终通过按列来源拆分谓词，将跨表条件保留在 join 阶段，并显式维护每个计划节点所需列集合，解决了语义错误和输出列不稳定的问题。

### 题目五：聚合函数与分组统计

本题实现了 `COUNT`、`MAX`、`MIN`、`SUM`、`AVG`，并支持 `GROUP BY`、`HAVING`、`ORDER BY` 和 `LIMIT` 的组合查询。整体做法是在执行层增加聚合算子：先读取子执行器输出的元组，再按分组键维护聚合状态，最后统一生成结果记录并进行排序、限制和格式化输出。

本题反复卡在隐藏测试的格式和边界语义上，尤其是聚合别名、默认表头、`COUNT(*)` 与 `COUNT(col)`、空结果聚合、`HAVING` 条件以及 `SELECT` 中非聚合列合法性检查。最后的处理方式是把普通列、分组列和聚合表达式在分析阶段明确拆开，执行阶段统一维护聚合中间值，输出阶段集中格式化整数、浮点数和字符串，避免各函数分散处理导致格式不一致。

### 题目九：可配置的快照隔离与可串行化隔离级别

本题在事务管理模块中实现了快照隔离和可串行化隔离。主要思路是为事务维护开始时间戳、提交时间戳和记录版本链，读操作根据事务快照选择可见版本，写操作进行写写冲突检测；在可串行化隔离下额外记录读集合和谓词读信息，用于发现可能破坏串行化顺序的并发写入。

开发中主要问题集中在 `Deadlock`、`UpdateTest` 和版本重构相关用例。早期实现中，更新语句对旧版本、新版本和同一事务自写可见性的处理不够统一，abort 后临时版本和锁状态也可能残留，导致后续事务读到错误版本或冲突判断异常。最终将版本可见性、写冲突检测、abort 清理和索引同步集中到事务管理器中处理，使执行器只负责发起读写请求，减少了状态分散带来的不一致。
