# 索引写入避免优化

本文记录减少索引写入争用的通用优化。

## 优化点

旧的 UPDATE 执行路径对每个索引都执行“删除旧键，再插入新键”，即使 UPDATE 没有修改任何索引列。TPC-C 中 Stock、District、Customer、Orders 和 OrderLine 的常见更新大多只修改非索引字段，因此会产生无效 B+ 树写入和额外表写锁持有时间。

## 优化方法

- 在 UpdateExecutor 中逐个比较旧记录和新记录的索引列字节。
- 只有索引键实际变化时，才执行新键唯一性检查、旧索引项删除和新索引项插入。
- 无变化的索引跳过维护；记录页更新、WAL、MVCC 版本和事务写集流程保持不变。
- IxScan 在范围遍历期间固定当前索引叶页，跨叶页时才切换页面；避免每条 RID 都重复 fetch/unpin 同一叶页，并在页面释放前复制 RID。

## 优化原因

减少无效的 B+ 树修改可以缩短写事务关键路径，降低索引叶页分裂、重定位与全表写锁之间的竞争。该优化不尝试在缺少页级锁耦合的现有 B+ 树中直接并发修改不同叶页，因此不会以牺牲索引一致性换取吞吐量。

## 验证

- `cmake --build build --target rmdb -j2` 已通过。
- 探针脚本：`python3 z_per/perf_tests/index_update_maintenance_probe.py`。
- 脚本验证非索引字段更新后主索引和二级索引仍可查询；也验证修改索引字段时旧二级索引项被删除且新索引项正确建立。
- 范围扫描探针：`python3 z_per/perf_tests/index_range_scan_probe.py`，验证跨多个索引叶页的范围扫描结果。

## 后续方向

真正提升不同键并发写入需要为 B+ 树页面、记录页位图和缓冲池生命周期建立页级锁耦合。该改造必须与 Phase 2/3 的并发一致性、回滚和崩溃恢复测试一起完成，不能仅移除表级锁。
